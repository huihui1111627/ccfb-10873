# ClaimNet · 车险团伙欺诈挖掘平台

把理赔、保单、查勘三单里的**人、车、电话、银行卡、地址、修理厂**连成关系网，
自动划分团伙、算可解释的风险分、推送图变化提醒，并把调查结论回流到评分模型。

单看每笔理赔都正常，但同一拨人换着车牌和修理厂反复出险 —— 这个平台就是用来把
"同一拨人"从 2800 笔理赔、2200 多个人里挖出来的。

---

## 快速开始

```bash
python3 run.py                      # 首次运行：生成数据 → 建库 → 分析 → 起服务
# 打开 http://127.0.0.1:8000
```

依赖只有已经装好的这些：`fastapi uvicorn networkx pandas numpy`。前端
Cytoscape 已 vendor 到 `frontend/vendor/`，**离线可用**。

其它入口：

```bash
python3 evaluate.py                 # 打印团伙级精确率/召回率报告卡
python3 evaluate.py --rerun --json reports/eval.json
python3 -m pytest tests/ -q         # 19 项算法与端到端测试
python3 run.py --regen              # 重新生成整套合成数据
```

## 评估结果（对照独立保存的真实团伙名单）

数据：2,843 笔理赔、2,263 人、160 家修理厂、**45 个植入团伙**（其中 52 名成员
被设计成"只通过一跳弱关联挂上核心"）。

| 指标 | 精确率 | 召回率 | F1 |
|---|---|---|---|
| 团伙级（双向重合 ≥80%） | **97.8%** | **100%** | **98.9%** |
| 人员级 | **98.9%** | **100%** | **99.5%** |
| 仅弱关联挂接成员 | — | **100%**（52/52，全部归属正确） | — |

45 个真实团伙全部检出，预测 46 个（1 个误报，是共用银行卡的背景巧合簇，51.3 分、
3 人）。评分最高的前 30 个团伙恰好覆盖 30 个真实团伙，排序质量没有虚高。

> 严格匹配要求预测团伙与真实团伙**双向**重合 ≥80%。因此"多带一两个可解释的
> 弱挂接成员"只体现为人员级 FP，不会被算成整个团伙的误报 —— 这是调查场景下
> 更合理的口径，报告中同时给出 ≥50% 的多数匹配口径。

## 数据长什么样

`python3 -m claimnet.synth` 生成，`data/ground_truth.json` **只给评估和测试用，
检测流程从头到尾不读它**。

- 身份证是 18 位、校验位正确的合成号；银行卡过 Luhn；车牌/车架号唯一。
- 保单、理赔、查勘三张表通过 `policy_no` / `claim_no` / `survey_no` 关联。
- **45 个团伙，四类作案手法**：
  - `collision_ring` 三者车互碰闭环：A 撞 B、B 又撞 A，来回刷赔付
  - `shop_burst` 修理厂集中出险：同一家厂 60 天内扎堆十来笔
  - `identity_swap` 身份共用 + 角色互换：共用电话/银行卡，被保险人和三者来回换
  - `mixed` 混合手法
- 每个团伙带 **1–2 名"弱挂接"成员**：只在住址上和某个核心成员重合一跳，
  自己的电话、银行卡、理赔、修理厂全部独立 —— 专门用来验证平台能不能靠一条
  弱边把人捞出来。
- **诱饵簇**（假阳性压力）：共用座机的多代同堂家庭、公司车队、只认一家厂的
  老客户、共用一辆车的网约车司机、地址+电话都同的家庭作坊。它们结构上像团伙，
  但缺少欺诈行为特征。

## 处理流程

```
三单原始文档
   │  claimnet/etl.py           入库（孤儿赔案会被丢弃并记账）
   ▼
实体关系抽取  claimnet/graph.py
   ├─ 异构图：person / vehicle / phone / bank_card / address / repair_shop / claim / survey
   └─ 人物亲和图：7 类关系加权，每条边都留原始证据（哪个电话、哪天、几次）
   ▼
团伙划分  claimnet/detect.py
   ① 强核心：本源强关系(共用电话/银行卡/三者互碰)构成的连通簇
   ② 弱挂接：只通过一条纯弱关系(如一个住址)挂到**同一个**核心的人
   ▼
模式识别 + 风险评分  claimnet/patterns.py
   修理厂 60 天窗口集中出险、三者车互碰闭环、9 个特征各给分并写明理由
   ▼
快照对比 / 反馈校准 / 证据链报告  snapshot.py / feedback.py / report.py
```

### 为什么"强核心"必须含本源强关系

同事故意 + 同修理厂两条弱关系加起来能到 0.52，看起来像"强"。如果不限制，
两个偶然在同一家厂修过车的陌生人会被并进团伙，再顺着 co-claim 把整个背景人群
连成一个上千人的巨环（开发过程中真实发生过，连接度一度达到 1832 人）。
所以强核心判定要求**至少一条关系本身是强的**。

### 弱关联参数可调

关系权重与时间窗都在 `claimnet/config.py`，也能在界面"权重与评分"里改并即时重算：

| 关系 | 权重 | 时间窗 | 说明 |
|---|---|---|---|
| 共用电话 | 1.00 | 730 天 | 强 |
| 共用银行卡 | 0.95 | 730 天 | 强 |
| 三者车互碰 | 0.85 | 365 天 | 强 |
| 同车驾驶 | 0.55 | 730 天 | 强 |
| 同一事故 | 0.40 | 365 天 | 弱 |
| 同一住址 | 0.25 | 365 天 | 弱 |
| 同一修理厂 | 0.12 | 120 天 | 弱 |

重复出现同一关系有封顶加成（最多 2×）。

## 界面

| 工作区 | 能做什么 |
|---|---|
| **总览** | KPI、最高风险团伙、图更新提示、评分权重构成 |
| **案件导入** | 拖 JSON 文件按名称自动归位；也支持增量导入只追加新赔案 |
| **关系网络** | 任意节点展开 1–3 度；自研环形 BFS 布局，2500 节点量级不卡 |
| **团伙列表** | 按评分/状态/批次筛选；每张卡带前三条评分理由 |
| **模式识别** | 修理厂集中出险、三者车互碰闭环两个榜单 |
| **变化对比** | 任意两个批次对比：延续/新增/消失团伙、**新增成员逐个点名** |
| **调查工作台** | 证据链、成员表、关联理赔、确认/排除按钮 → 模型即时升版 |
| **评估** | 真实团伙逐个检出情况 + 误报团伙 |
| **权重与评分** | 改弱关联权重/时间窗/特征权重/报告阈值，保存后重算 |

### 上千节点为什么不卡

- **环形 BFS 布局**：按图距离分层，每层节点按父节点角度排序，纯 O(n)，1.5k 节点
  毫秒级；力导向在同样规模要 12 秒，已弃用。
- **标签策略**：超过 600 节点自动隐藏文字标签，只保留悬停/选中节点的标签
  —— Cytoscape 渲染上千个文字标签本身就比布局更贵。
- **扇出裁剪 + 时间窗**：修理厂/共用电话这类枢纽节点只跟权重最高、最近的
  40 条边，时间戳关系按 180 天窗口过滤。这条规则把某个高连接人的 3 度展开从
  1492 节点压到 **154 节点、244 条边**，且语义更准。
- 固定服务端硬上限 1800 节点 / 6000 边。

## 反馈闭环

调查员在案件上点"确认为欺诈"或"排除"：

1. 该团伙所有**已经触发**的特征权重按 `±0.12 × 特征强度` 调整；
2. 权重向量重新归一化，保证分数可比；
3. 模型版本 +1，历史留档（谁、什么时候、改了什么、为什么）；
4. **下一次**分析就用新权重 —— 不追溯改历史批次。

界面"权重与评分"页能看到每次校准的前后值。

**防过拟合**：如果连续 3 次只有"确认"、没有任何"排除"，学习率按 0.5 的幂次递减；
每个特征的权重被限制在初始值的 ±60% 以内、绝对上限 0.30。没有这层限制时，
连续确认同一个团伙十次能把所有特征推到封顶，评分器就变成"什么都像团伙"。
（实测：无防护时反复确认会把团伙级精确率从 97.8% 拉到 91.8%。）

## 报告

`GET /api/cases/{case_id}/report?download=true&fmt=md` 导出证据链报告，包含：
风险评分依据（每条多少分）、作案模式、成员与挂接依据、关系证据（哪个电话/哪天/
几次）、关联理赔明细、调查处理记录。HTML 版存到 `reports/`。

## 已知边界

- 数据是合成的。真实理赔的文档格式、缺失值、地址写法差异会大得多；
  解析层（`ClaimBook._load`）和地址归一化要按实际数据重做。
- "强核心含本源强关系"这条规则在小样本上会把共用座机的诱饵家庭判成团伙候选，
  靠行为特征评分（赔付、频次、短期集中）把它们压到阈值以下 —— 数据量越小，
  诱饵占比越高，越需要调阈值。
- 团伙 ID 每次重算都会重新编号，跨批次追踪靠成员重合而不是 ID，这是刻意的。
